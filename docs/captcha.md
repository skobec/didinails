# Капча от ботов (Cloudflare Turnstile, бесплатно)

На форме уже есть 3 бесплатных рубежа: honeypot, time-trap и rate-limit
(макс. 3 заявки в час с устройства). Капча — четвёртый, видимый:
галочка «я не робот» + **настоящая серверная проверка** токена внутри
транзакции записи. Прямой вызов API в обход виджета отклоняется.

Почему не SMS-OTP: SMS платные за каждое сообщение — противоречит принципу
нулевой стоимости MVP. Капчи + существующих рубежей достаточно для салона.

## Настройка (один раз, ~10 минут)

### 1. Применить миграцию 0007

SQL Editor → New query → `supabase/migrations/0007_booking_captcha.sql` → Run.
Без неё новый параметр игнорируется (старая функция его не знает) —
ничего не сломается, но и проверки не будет.

### 2. Завести Turnstile

- https://dash.cloudflare.com → Turnstile → Add site.
- Hostname: домен прода (`skobec.github.io`) **плюс** `localhost`
  (через запятую) — иначе локально виджет не заведётся.
- Скопировать **Site key** и **Secret key**.

### 3. Разложить ключи

- Secret key → в Vault (SQL Editor):
  ```sql
  select vault.create_secret('<TURNSTILE_SECRET>', 'turnstile_secret');
  ```
  (обновить: `select vault.update_secret('<TURNSTILE_SECRET>', 'turnstile_secret');`)
- Site key → `VITE_TURNSTILE_SITE_KEY`:
  локально в `.env.local`, в проде — Variables репозитория + Re-run сборки
  (ключ запекается в билд, как и Supabase-ключи).

## Как это работает

1. Клиент ставит галочку → виджет отдаёт одноразовый токен.
2. Форма шлёт токен вместе с заявкой (`p_captcha_token`).
3. `create_booking` сверяет токен с Cloudflare (`siteverify`) **до** создания
   клиента и записи. Не сошлось → `BAD_CAPTCHA`, записи нет.
4. Секрета нет в Vault → проверка пропущена (dev-режим, удобно тестировать).
5. Секрет есть, токена нет → `NO_CAPTCHA` (защита от обхода виджета).

## Честные ограничения

- Если у клиента блокировщик режет `challenges.cloudflare.com`, виджет не
  загрузится за 6 секунд — форма всё равно отправится, дальше решит сервер:
  без секрета пустит, с секретом попросит галочку (текст подскажет).
- Виджет виден только в cloud-режиме при заданном `VITE_TURNSTILE_SITE_KEY`.
  В local-демо и в ручном создании из админки (владелец и так доверенный)
  капчи нет.
- От целенаправленной атаки с фермой токенов не защищает — для салона
  такая угроза нереалистична; тогда уже Edge Function + поведенческий скоринг.
